# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

在这里作答。
区别就是Make更加的自动化和简便，build.sh 中所有文件的关系和每次编译等的指令还是得自己手写，但是Make我只需要告诉它目标，依赖哪些文件和路径，剩下的它自己完成（构建关系和编译等），可以说是make在我给的关系下能自动写出对应的build.sh

## 2. CMake 是编译器吗？

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

在这里作答。
最终还是编译器在编译。只是相比于我们直接输入`gcc - ...`，变成了`cmake --build build   ->   gcc - ... `多了一步，通过告诉cmake，让cmake去输入相关编译指令

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

在这里作答。  
我们大多数时候都希望高效，减少重复无意义的行为，make和cmake不就是为了避免我们像个牛马一样不断`gcc`或者`ctrl+c/+v` 
重新编译这件事也是一样，只需要编译改动的部分，再重新链接，这样子所需花费的时间等是最小的，其他地方在没有改动的情况下重新编译只是浪费时间和资源，尤其是在有特别多文件的时候。
